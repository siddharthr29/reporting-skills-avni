Claude does

Finds where the data is, writes the query, builds the card, runs the checks, drafts the reply.

You do

Explain what the client wants, answer Claude's questions, check the numbers make sense, approve changes.

🔒 Claude never sees people's personal details. The tools hide names, phone numbers, Aadhaar and dates of birth automatically. Never paste client lists or screenshots showing people's details into Claude.

Two things to remember. (1) We only ever READ data; we can't break the app. (2) Reports can be up to ~1.5 hours behind the app. That's normal, not a bug.

Get ready (one time, about 10 minutes)

  1. Get the reporting-skills-avni folder and the database access details from your lead. Ask your admin for your own Metabase API key.
  2. Open Terminal in that folder and run ./tools/setup.sh. Enter your own Metabase API key and Superset login. They're hidden as you type, and it checks they work.
  3. Type claude and paste the message on the right.

Never use someone else's logins, and never paste a password into Claude.

If Claude asks permission to run something, read what it says, then allow it. If it gives you a line starting with !, copy and paste it. That's you approving the change.

You typeSet me up for reporting: open the read-only connection and download the data map for <org name>. Tell me in simple words when it's ready.

Download the data map for every NGO before building anything. Claude reads this file instead of searching the live system, which is faster and cheaper. The tools won't run without it.

Do this on the projector once, then let everyone do it. Common problem: the settings file is missing or in the wrong folder. Claude will say so in plain words.

Step 1 · Give Claude the requirement sheet

Requirements usually come as a Google Sheet or Excel file, one row per indicator. Claude reads every tab and sorts the rows for you.

Every ❓ is answered. Don't know an answer? Ask your lead or the client. Don't guess. Build the ✅ rows first.

Most real work starts from a sheet. The ✅/❓/⛔ table is the key habit: we agree on the unclear rows before building, not after. "Not in the data" is a normal, honest answer.

Step 2 · See the numbers before building anything

Claude finds the data and shows you the result. Nothing is created yet. This is where you catch mistakes early.

You typeUsing the data map, find where children and their villages are stored and explain it in simple words. Then show me the number of children per village (top 10) and the total. Don't create anything yet.

Number looks wrong? Just ask: "The app shows 1,300 but you show 1,248. Why could that be?" Claude knows the usual reasons: deleted records, children who left, data not copied over yet.

Step 4 · Check it like the client would

Open the link yourself and click around. Five checks catch almost every problem we've seen.

  • It opens within a few seconds
  • The filter is a dropdown (not a box you type in), and picking a village changes the numbers
  • Click the number: the list has the same count as the number (212 → 212 rows)
  • All villages add up to the total
  • No strange codes like 3f2a9c1e-… in the list
Then you typeRun the checks on this report and tell me in simple words if anything is wrong.

Something's off? Describe what you see, in plain words:
"When I click 212, the list shows everyone."
"The village filter is a typing box."
Claude looks up how that problem was fixed before, and fixes it.

✓ Move on when

All five boxes are ticked, and Claude's checks say everything matches.

These five checks map to the most common tickets we've had: slow reports, text-box filters, clicks showing the wrong list, totals that don't add up, raw IDs. Interns don't need to know why. They need to notice.
