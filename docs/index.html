Why the catalogue saves tokens

Instead of 20+ information_schema round-trips per session, the agent greps one compact file (illustrative excerpt):

## individual_child_growth_monitoring (~1,756,119 rows)
"Weight" numeric ~12% null · "Height" numeric ·
"Weight for age Status" text [Normal|MUW|SUW] · …
## session_coded (~9,412 rows) — coded EAV: one row per answer
## class_session … "Students present" text UUID-array
  • Coded values, empty columns, UUID arrays and _coded tables are flagged for you
  • Gitignored: never committed. Re-dump on "column does not exist"
Do this live on a UAT schema. Point out the read-only proof: the tunnel refuses to continue if a write succeeds. Show one grep: grep -n -i weight schemas/…/CATALOG.md. The file is gitignored because coded values are real data.

"Build the card from the base-CTE shape with Block and Date filters, apply the dropdown recipe, and give me a per-metric drill. Dry-run first."

Golden rules

  • Prod is read-only. No DDL, no indexes, no writes
  • Patch in place. Never recreate: links are bookmarked
  • Reuse template tags when changing card SQL
  • Back up before every PUT (tools do it)
  • Read the whole ticket: Freshdesk pages at 10 messages
  • Prove, then claim
Emphasise step 1: most rework came from a definition we didn't pin down (enrolled vs registered, roster vs attendance). Step 7 is how the pack improves: every session ends with a learning check.
Data model
7 min

Eight data traps that caused real tickets

1 · Voided rows

is_voided=false on every join, except "people who left": exits void the membership link.

2 · Multi-selects

ILIKE '%Baseline%' matched "Baseline, Other". Use the _coded table.

3 · UUID arrays

Attendance and pickers are JSON UUID lists. Unnest and join to names, never show UUIDs.

4 · Double counts

One person in 2 groups → counted twice (21,761 vs 21,525). DISTINCT ON.

5 · Roster vs activity

INNER JOIN on attendance showed 173 of 200 children. LEFT JOIN + status filter.

6 · Latest non-null

Latest row said "not recovered". The latest value said recovered: 0/0/1 → 2/1/14.

7 · NULL dates

NULL encounter_date_time = scheduled. Cancelled ≠ done. NULL months can't be drilled.

8 · Stale schema

"WEIGHT"→"Weight" broke 6 cards. Re-dump, then sync_schema in Metabase.

Each card is a real org: Gubbachi (voided exits), Durga (multi-select), Khel Mel (roster), Maitrayana (double count), Sangwari (latest non-null, WEIGHT rename). The full list of 18 traps is in skills/avni-etl-data-model.
Filters & drill-downs
10 min

Two recipes that fix most filter and drill tickets

Dropdown, not a text box: set both levels

// dashboard parameter
"values_query_type": "list", "values_source_type": "card"
// card template tag (kebab-case) AND card parameters[] (snake_case)
"values-query-type": "list", "values-source-type": "card",
"values-source-config": {"card_id": <VALUES_CARD>, "value_field": [...]}

Only the dashboard set → the card page is still free text. The values card excludes voided rows.

Filter "does nothing" on a card?

The card has no tag or mapping for it, so it is silently ignored. Run mb.py dash <id> to list unmapped filters.

Drill shows everyone? One drill card per metric

drill = same base CTE + metric's condition + same dedup
click_behavior → targetId: <DRILL>
  target: {"type": "variable", "id": "block"}   // not "parameter"
  pass EVERY dashboard filter through

The 60-second drill test

Metric with Block = X → click → count rows. Equal = done. Not equal → EXCEPT ALL the two row sets.

Also: read cards via stages[0] (new API shape), reuse tags on edit, (drill) [KEY] names.

Demo: open a card whose filter is a text box, run mb.py card, and show the missing tag-level setting. Then the drill: Gubbachi "Absent shows Present", Sangwari's 105 generated drills. All 47 cases are in playbooks/filter-issues.md and drilldown-issues.md.
Superset & Jasper
7 min

Superset and Jasper: what's different

Superset

  • Login + CSRF token with a cookie jar on every write
  • Datasets are virtual SQL, computed in full before filters and RLS apply
  • SQL changed? Refresh the columns or you get X__1 does not exist
  • Charts need query_context (400 otherwise). Link from the chart side
  • Native filters live in native_filter_configuration. Clone one, keep the rest
  • Drill = cross-filters. 60s timeout kills downloads
  • RLS rules on a dataset AND-combine

Jasper (legacy): diagnose + safe edit

  • Same ETL SQL, inside JRXML <queryString>
  • $P{x} bound · $P!{x} spliced raw (location RLS)
  • Debug: extract the SQL, substitute params, run it read-only
  • Edit: export/download → change the text → Studio for layout → a human uploads (auto-versioned)
  • Reports are copied per level × fiscal year, so patch all copies

RWB example: one new column meant 8 JRXMLs, each verified read-only.

If the org asks for something new in Jasper, steer them to Metabase or Superset. For Superset, the two things that bite most are query_context and the column refresh.
Speed & safety
7 min

Prove it's the same data, then make it fast

APF Odisha: "the line list won't download"

A permission fix didn't solve it. The first idea (an infra index) would have been a needless escalation. The real cause was a CTE sorting 1.6M rows on every load whose columns were never selected.

2–5 min → 0.8 s

with a as materialized (<old>), b as materialized (<new>)
select count(a), count(b), a EXCEPT ALL b, b EXCEPT ALL a   -- 68,577 · 68,577 · 0 · 0 ✓

tools/qa.py except-all old.sql new.sql

Fixes, in order to try

  1. Delete dead CTEs
  2. AS MATERIALIZED (103s → 1.1s)
  3. Materialised concept lookup (41s → 0.7s)
  4. LATERAL top-1 per entity
  5. ETL tables, not public.*_view
  6. LIMIT 2000 on line lists

No DDL on prod, ever.

The story is the lesson: check access AND timeout (they look identical to users), prove before escalating, and never ship a rewrite without EXCEPT ALL = 0 both ways.
