How Avni reports fit together

One picture and five words. That's all the background you need.

Avni appfield workers enter data
Report copyrefreshed every ~1.5 hours, so reports can lag a little
Metabasethe website where reports live
Clientopens the report link

Five words

Cardone number, chart or table
Dashboarda page with several cards
Filtera dropdown to narrow the numbers, e.g. pick a village
Click-throughclick a number to see the list behind it
Data mapa file listing every table and column of one NGO

Who does what

Claudefinds the data, writes the query, builds the cards, runs the checks, drafts the reply
Youexplain the request, answer questions, check the numbers make sense, approve every change

Privacy. Claude never sees people's names, phone numbers or IDs. The tools hide them. Never paste client lists or screenshots showing people's details into Claude.

Two things to land: we only ever read data, so nothing in the app can break; and reports trail the app by up to ~1.5 hours, which is normal.

Get ready (once, about 10 minutes)

Do these in order on your own laptop.

  1. Open Terminal (Mac: press ⌘ Space, type Terminal, press Enter).
  2. Copy the first box on the right into Terminal and press Enter.It downloads the pack and opens its folder.
  3. Type ./tools/setup.sh and press Enter. Enter your own Metabase API key and Superset login.Nothing shows while you type a password. That's normal. Never use someone else's logins.
  4. Type ./tools/tunnel.sh up. Wait for "read-only proven".
  5. Type claude, then paste the second box with <org name> replaced by the practice NGO.

Type exactly · Terminal

git clone https://github.com/siddharthr29/reporting-skills-avni.git
cd reporting-skills-avni

Type exactly · Claude

Set me up for reporting: open the read-only connection and download the data map for <org name>. Tell me in simple words when it's ready.

Claude replies, something like

Connected, read-only: I can look at data but can't change anything. Data map saved for this NGO.

Before you move on

Walk the room here. Most common problems: no Metabase API key yet (an admin creates one per person), or a wrong SSH key path. Setup says which.

Step 1 · Give Claude the requirement sheet

Requirements usually arrive as a Google Sheet or Excel file, one row per indicator.

  1. Open the client's requirement sheet.
  2. Google Sheet: click Share → General access → Anyone with the link → Viewer → Copy link.Can't share it? Use File → Download → Microsoft Excel, and give the file path instead.
  3. Paste the box on the right into Claude, with your link or file.
  4. Read Claude's table. Answer every needs clarification question.Don't know? Ask your lead or the client. Never guess.

Type exactly

Read AGENTS.md. Here is the requirement sheet for <org name>: <link or file path>. Read every tab and show me each requirement marked buildable, needs clarification, or not in the data.

Claude replies, something like

I read 3 tabs, 12 requirements:

  • 9 buildable, e.g. "Children per village"
  • 2 need clarification: does "active" include children who left?
  • 1 not in the data: "Screening done" isn't recorded

Before you move on

The most important habit. Most rework we've had came from one unclear word, like "registered" vs "enrolled". "Not in the data" is a normal, honest answer.

Step 2 · See the numbers before building anything

Nothing is created in this step. This is where you catch mistakes cheaply.

  1. Paste the box on the right into Claude.
  2. Write down the total Claude shows.
  3. Compare it with a number you trust: the client's sheet, the field team, or the Avni app.
  4. Different? Type: "The app shows X but you show Y. Why could that be?"Claude knows the usual reasons: deleted records, children who left, data not copied over yet.

Type exactly

Using the data map, find where children and their villages are stored and explain it in simple words. Then show me the number of children per village (top 10) and the total. Don't create anything yet.

Claude replies, something like

Children are in the child register, and each child's village comes from their address. I left out deleted records and children who left.

Village A 212 · Village B 164 · Village C 118 … Total 1,248

Before you move on

Teach the habit of comparing with something real. If Claude can't explain a difference in simple words, stop and ask the lead.

Step 3 · Build it: plan, approve, get a link

Claude shows exactly what it will create, and builds only after you say yes.

  1. Paste the box on the right into Claude.
  2. Read the plan. Check it says practice folder.Never change a client's live report without your lead.
  3. Type Yes, go ahead.
  4. If Claude gives you a line starting with !, paste it back into Claude and press Enter.That's you approving the change. A backup is saved first.
  5. Click the link Claude gives you.

Type exactly

Create this report in our practice folder: the total number, a bar chart by village, a Village dropdown filter, and make the number clickable to show the list of children. Show me the plan first.

Claude replies, something like

Plan: 3 cards (the total, clickable; a bar chart by village; the list of children) and a Village dropdown connected to all three, in the practice folder. Nothing changed yet. Shall I create them?

Before you move on

"Show me the plan first" is the safety habit. Nothing happens until they say yes.

Step 4 · Click it like the client would

Do each click yourself. These catch almost every problem clients have reported.

  1. Open the link. It should load in a few seconds.
  2. Click the Village filter. It must open a list, not a box to type in. Pick the first village.
  3. The numbers change. Write down the total.
  4. Click that number. At the bottom of the list Metabase says "Showing N rows". N must equal your number.
  5. Scroll the list: there should be no long codes like 3f2a9c1e-….
  6. Paste the box on the right. Claude checks the rest, including folders and who can open it.

Type exactly

Run the checks on this report, including with one village selected, and show me the Definition of done as ticks and crosses.

Something wrong? Describe what you see

"When I click 212, the list shows everyone."

"The village filter is a typing box."

Claude finds how that exact problem was fixed before, and fixes it.

Before you move on

These clicks map to the most common client complaints: slow reports, text-box filters, clicks showing the wrong list, raw IDs. Interns don't need to know why, only to notice.

Step 5 · Deliver, then build your own

  1. Paste the first box. Send Claude's draft reply to your lead, not the client.
  2. Paste the second box, with the team that needs the report.
  3. Type /learn. It saves anything new for the next person.

Type exactly

Write a short, friendly reply to the client: what we built, how to use the village filter, and the link. Only mention what we checked.

Type exactly

Give the <team> group access to every folder of this report, then show me the permission check.

Your turn · 20 minutes · in pairs

"How many home visits happened each month? Let us pick a month, and click to see the visits."

  1. Do steps 1–5 again for the practice NGO.
  2. Use the same boxes. Change only the words about children and villages.
  3. Stuck? Ask Claude: "Which playbook covers this problem?" or open START-HERE.md.

Done when

During the exercise, the two most common slips are skipping step 2 (not looking at the numbers) and not clicking through in step 4. Close by asking two pairs to show their report.
